# 后代调度设计

## 范围

在现有 Skill 上支持有界后代编排，并新增无依赖的 planctl.py。工具读取 schema 2 JSON 计划，验证结构/依赖，生成中文 Review Markdown，以及根据执行状态计算 launch/aggregate/accept 前沿；不操作 Orca、不写 Task 状态、不实现后台调度器。

## 契约

- 计划包含 root_task、nodes（稳定 Task ID、完整已知直接子 ID 与选定有序 children、依赖、验收标准、Agent/terminal）、外部依赖快照。
- 有选定子节点者为协调汇总节点；叶子是执行节点。未展开但有已知子节点者不允许默认为叶子执行，避免隐藏后代范围。可采用单独直接子任务计划，由既有协议处理显式不展开的父节点。
- 默认根验收串行；各父节点 mode 向下继承，支持覆盖。子节点验收由父节点模式确定：manual-sequential 人工；auto-sequential/parallel 协调者检查；根最终验收默认人工。
- 为每节点建立进入与验收两个阶段。进入依赖父节点进入、串行前项验收、显式依赖验收；汇总验收依赖选定子节点验收。先进行组合图判环，捕获普通依赖环及祖先/后代、串行顺序造成的死锁。
- 选集允许部分分支，但必须包含到根的祖先链；完整 known_children 列表用于展示排除项。完整覆盖自底向上推导；部分覆盖节点可汇总所选批次，但不得释放以完整 Task 为目标的依赖，不得标记整个 Task 完成。
- Review digest 覆盖完整策略（包含 plan_version、节点范围、顺序、模式、验收条件和 Agent/terminal）；动态 runtime/revision/review/authorization 不参与。ready 在 Review 未批准、摘要不匹配或无执行授权时不返回可执行动作。
- 运行记录引用同一策略摘要，防止旧状态附着到新方案。工具只消费记录；协调者负责根据真实回执和验收结果持久化。输入状态只能被校验一致性，不能代替真实证据核对。
- 汇总和验收是两步，不因子节点完成自动验收父节点。父节点不自动创建 terminal。launching/running/unknown/failed 均不能重复启动。

## 验证

模拟两级混合策略、深层继承/覆盖、选定分支、跨层依赖、死锁、待人工验收、过期 Review、过期状态、恢复 unknown、重复启动、失败停止等。渲染和前沿同源。仓库现有测试及 Skill 校验完整运行。实际 Orca 启动仍未授权实测，不宣称端到端成功。
